# 문서 비교실 (웹앱 v0.2)

로컬 파일 2개를 브라우저 안에서 읽고 비교하는 정적 웹앱입니다. 별도 백엔드와 계정 로그인은 없습니다. 문서 파일 자체를 서버에 업로드하지 않습니다.

## 기능

- PDF / XLSX / HWPX 파일 선택, 서로 다른 형식 조합 허용
- 빠른(텍스트), 정밀(텍스트·추출 가능한 서식·PDF 화면 보조 비교), 화면(픽셀) 모드
- 전체 / 페이지 범위 / 좌우 페이지에서 직접 드래그한 영역 비교
- 원본·수정본 미리보기 위에 차이점 표시
- 이전·다음 차이 이동, 추가·삭제·수정·확인 필요 필터
- 결과를 JSON 파일로 저장
- 엑셀: 셀 값, 행 식별자, 일부 글꼴·테두리·수식 비교
- 한글 HWPX: 문단·표 셀 단위 추출
- PDF: 실제 페이지 렌더링 및 텍스트 추출, PDF끼리 화면 보조 비교

## 현재 한계 (필독)

1. **구형 `.hwp`는 지원하지 않습니다.** 한컴오피스에서 `.hwpx` 또는 `.pdf`로 저장하세요.
2. **XLSX·HWPX 미리보기는 구조 기반 재구성 화면입니다.** 실제 Excel/한글 인쇄 페이지의 줄바꿈·표 좌표·여백이 동일하다고 보장하지 않습니다.
3. **HWPX 스타일, Excel 계산 결과 갱신, 수식 실행, PDF OCR은 미지원**입니다. 스캔 PDF에는 선택 가능한 텍스트가 없다면 화면 비교를 사용하세요.
4. 교차 형식의 표 항목 대응은 **행 전체 특징값·고유 식별자·열 위치·텍스트 유사도**에 의존합니다. 같은 항목이 반복되는 문서에서는 오탐·누락 가능성이 있습니다.
5. 픽셀 비교는 브라우저의 축소 이미지에서 타일 단위로 검사합니다. 1픽셀/매우 얇은 선 차이를 놓칠 수 있으며, 배치가 다른 문서의 시각 차이는 실제 내용 차이가 아닐 수 있습니다.
6. 화면 비교는 기본적으로 **양쪽의 같은 페이지 번호끼리** 처리합니다. 페이지 삽입·이동 정렬은 아직 지원하지 않습니다.
7. 최초 버전 안전 범위: 파일당 80MB, PDF 300페이지, XLSX 시트당 생성 미리보기 200페이지. 이보다 크면 범위를 나누어 비교하세요.
8. PDF의 폰트 정보나 의미 구조가 추출되지 않을 수 있습니다. 비교 불가능한 항목을 완전히 같다고 보장하지 않습니다.

## 실행

웹앱 링크로 접속한 다음 파일 A와 B를 선택하고 비교 모드와 범위를 지정해 **비교 시작**을 누릅니다. 설치가 필요 없습니다.

로컬 복사본은 `dist/`를 정적 웹 서버에서 제공하면 작동합니다. ES Module 및 PDF.js Worker 때문에 `file://`로 HTML을 직접 여는 방식은 지원하지 않습니다. 예시: Python 설치 환경에서 프로젝트 루트에서 `python -m http.server 8000 -d dist` 실행 후 `http://localhost:8000/` 접속.

## 행 삽입·삭제·이동 비교

- 자동 식별자 탐색 또는 A~I열 직접 지정, 식별자 없이 비교 선택
- 고유 식별자 및 행 전체 내용의 고유 앵커를 먼저 대응하고, 증가 부분 수열과 구간별 LCS로 순서를 정렬
- 행 번호가 바뀌어도 대응 행의 같은 열끼리 내용/추출 가능한 서식을 비교
- 같은 시트 수식의 참조 행도 대응 행 번호로 정렬하여 자동 참조 이동을 추가 변경으로 세지 않음, 다른 시트 참조 수식 변경은 검토 필요로 표시
- 삽입/삭제는 셀 수가 아닌 행 1건으로 표시, 실제 순서 이동은 별도 표시
- 중복 식별자/중복 행/비슷한 대응 후보는 확인 필요 표시, 큰 모호 구간은 예산을 제한해 검토 대상으로 반환
- XLSX 화면 모드는 위치가 이동한 페이지 전체를 픽셀 비교하지 않고 정렬된 행의 내용·가용 서식 결과를 사용
- 구조 비교는 Web Worker에서 처리하여 화면 멈춤을 줄임

## GitHub Pages와 Sites

웹앱 주소: https://box195.github.io/docdiff-studio/

사용자 요청에 따라 2026-10-28에 GitHub 저장소를 공개로 전환하고, `gh-pages` 브랜치 루트를 GitHub Pages 게시 소스로 설정합니다. 원본 소스는 `main`, 웹 실행 파일은 `dist/`에 있습니다. 문서는 브라우저 안에서 처리하며 서버에 업로드하지 않습니다.

수정본을 배포하려면 테스트와 main 커밋/푸시 후 `git subtree split --prefix dist -b pages-release`, `git push github pages-release:gh-pages`를 실행합니다. Pages 배포는 해당 브랜치 푸시로 갱신됩니다. main만 푸시하면 배포가 갱신되지 않습니다. 재배포할 때는 아직 사용하지 않은 로컬 브랜치 이름을 지정하세요.

기존 Sites 배포 및 접근 정책은 유지하며, GitHub Pages와 별도로 동작합니다. 기존 Sites 주소에 이 수정본을 재배포하지 않았습니다. 기존 Sites 원본 소스 커밋 `69a198c3e0cc9c4d3fece1de57936554627c6f5b`에서 복구했습니다.

`dist/`가 실행 가능한 정적 웹앱이며 Windows EXE 설치 파일은 아닙니다. 소스·필요한 브라우저 라이브러리를 모두 포함합니다.

## 검증

`npm ci` 후 `npm test`로 자동 테스트를 실행합니다. 2026-10-27 수정본의 Node 테스트 28/28 통과: 동일, 한 셀 변경, 100행 중간 한 행 삽입, 여러 행 삽입, 삭제, 이동, 중복 행, 중복 ID 검토, 빈 행 삽입, 서식 변경, 삽입 후 서식 변경, 식별자 열, 교차 형식, XLSX 화면 모드, 영역 범위, 공백, 5,000행 성능, 실제 XLSX/HWPX/PDF 파싱 및 미지원 형식 안내를 확인했습니다.

5,000행 합성 문서의 단일 삽입 비교는 이 PC에서 약 0.2초였습니다. 테스트 파일은 메모리에 생성한 가상 자료와 기존 Sample PDF만 사용합니다. 실제 사용자 문서는 저장소에 포함하지 않습니다.

`/selftest.html`은 기존 브라우저 파싱·렌더링 검사용 화면입니다. 이전 버전의 11개 테스트를 유지하고 행 삽입 판정을 행 단위로 갱신했습니다. 이번 수정본의 실제 브라우저 UI·렌더링·Web Worker 실행은 도구 제약으로 재검증하지 못했습니다. Node의 PDF 텍스트 추출 테스트는 통과했지만 파일 URL 글꼴 로딩 경고가 발생하여 브라우저 PDF 렌더링 검증과 구분해야 합니다.
